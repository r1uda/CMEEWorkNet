# CMEE事务组协作开发

代码仓库计划使用私有仓库 `r1uda/cmee-work`。受邀协作者为 `HwangXP`；邀请是否发送和接受，以 GitHub 的实际状态为准。

## 本机运行

安装 Python 3.11 或更高版本，在项目根目录运行：

```powershell
python -m app.server --demo
```

打开 http://127.0.0.1:8765 。演示模式使用独立数据库，不发送邮件、不调用外部 AI。首次查看请选择演示身份。前端是原生 HTML/CSS/JavaScript，没有 npm 构建步骤。

如需本机联调外部服务，复制 `.env.example` 为 `.env`，填写自己的测试服务配置。成员数据库、正式服务凭证、Quill 安装包均不随源码分发。没有安装包时下载接口返回 404，其余开发功能可正常使用。

## 目录

- `app/static/app.js`、`style.css`：页面逻辑、手机和电脑布局。
- `app/service.py`、`handoff.py`、`public_swap.py`：登记、交接和换班业务。
- `app/public_swap_mail.py`、`workflow_mail.py`、`mailer.py`：邮件内容、队列和发送。
- `app/ai.py`：AI 接口和受权限控制的数据查询、操作提案。
- `app/migrations/`：数据库增量迁移；当前代码版本为 schema 11。
- `tests/`：使用临时数据库、模拟邮件与模型的自动检查。
- `deploy/`：Linux 服务和反向代理部署模板。`install.sh` 仅供首次安装，不能用来覆盖正式数据库。

## 提交修改

1. 从最新主分支创建自己的分支，例如 `hwangxp/fix-mobile-layout`。
2. 修改后本机运行演示，检查相关手机和电脑页面。
3. 按改动运行相关测试；涉及业务规则或权限时增加相应用例。
4. 推送分支，在 GitHub 发起 Pull Request，写明改动目的与检查结果。
5. 检查后合并，再由维护者单独部署正式网站。

```powershell
python -m unittest discover -s tests
node --check app/static/app.js
node tests/frontend_smoke.cjs
```

Python 测试不需要第三方依赖。Node 仅用于可选的前端检查。

## 正式网站更新

GitHub 提交不会自动修改 https://cmee-work.top 。目前采用单独部署，部署前应保存代码和数据库备份，检查数据库迁移，再更新代码并重启服务。不能用本机演示库覆盖生产库，也不能在多人电脑上同时运行正式提醒任务。

本仓库包含固定成员姓名、职责和应用代码，因此保持私有。成员邮箱、排班与事务记录、登录会话、密钥、云平台订单和部署截图不上传。不要使用 `git add -f` 绕过这些排除规则。新增文件提交前检查 `git diff --cached`。
